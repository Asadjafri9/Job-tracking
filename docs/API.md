# HTTP and browser contracts — version 2

FastAPI Pydantic/OpenAPI is authoritative at `/api/v1/openapi.json`; run `pnpm generate:contracts` to refresh `docs/openapi.json` and the generated TypeScript contract, and `pnpm verify:contracts` to check for drift. Prefix `/api/v1`, snake_case JSON, UUIDs, RFC3339 UTC instants, ISO dates. Unknown writable fields rejected. Protected requests derive owner from app session, require ACTIVE account and CSRF/exact Origin for cookie mutations. Extension uses opaque bearer token plus exact Origin/version. Owner-scoped resources return 404 for another user.

This document records the target API contract, including routes that are still backlog items. Use generated OpenAPI and `docs/TASKS.md` to distinguish implemented endpoints from planned ones; only the metadata and current auth/credential routes are implemented in this milestone. The checked-in OpenAPI and TypeScript snapshots have not yet been regenerated for those routes because the API environment dependencies are unavailable.

## Shared response behavior

Errors use the stable `{error:{code,message,request_id,field_errors:[]}}` envelope, with no secrets/raw personal content. Validation field entries contain a field path, stable code, and safe message; raw submitted values and validator internals are never returned. 401 auth, 403 blocked/CSRF/consent, 404 foreign/missing, 409 revision/idempotency/in-flight/duplicate, 410 deleted, 413 bytes, 422 validation/missing facts, 426 incompatible contract version, 429 quota, 502 provider/source outcome, 503 dependency unavailable. Protected responses are no-store; API failures never redirect to HTML. `X-Request-ID` is a validated UUID or generated by the API and is returned on the response. GET ETag quoted revision, update If-Match. Creates/operations/events use stable Idempotency-Key. Cursor pagination limit 1–50.

Identity endpoints: `GET /auth/login` begins a ten-minute OIDC state/nonce/PKCE transaction; `/auth/callback` consumes it once and returns web users to the configured `WEB_APP_ORIGIN`; `GET /auth/session` returns the account and session-bound CSRF token; `POST /auth/logout` requires exact Origin and CSRF and revokes all sessions. `/auth/extension/exchange` redeems a 60-second grant bound to extension ID, state and PKCE, and `/auth/extension/logout` revokes all account sessions. Local HS256 identity is allowed only in local/test; staging and production accept RS256 ID tokens from the configured issuer/JWKS.

Saved provider credentials use `GET /api/v1/provider-credentials`, `PUT /api/v1/provider-credentials/{provider}` and `DELETE /api/v1/provider-credentials/{id}`. Writes require an authenticated session, fresh authentication, exact Origin and CSRF. Responses expose only provider, last four characters, purpose consent, status and revision. `GET/PUT /api/v1/provider-settings` configures up to three ordered model routes and explicit interactive, fallback and background consent revisions.

`X-Copilot-Client-Version` and `X-Copilot-Contract-Version:1` identify extension contract. Client version uses strict numeric `MAJOR.MINOR.PATCH` (no prefix, whitespace or leading zeroes). `GET /api/v1/meta` returns `api_version`, `contract_version`, and the minimum compatible client version, not secrets. An explicitly supplied unsupported contract version, malformed client version, or client version below the minimum gets 426; both headers may be omitted while ordinary web routes are developed. Support current/previous compatible beta releases when they meet the published minimum. Added fields are compatible; removals/meaning changes require a new contract and migration.

For routes abbreviated `/{id}`, use the immediately preceding collection path. IDs cannot be caller-supplied owner selectors. Secret input uses SecretStr and request-body/APM logging is disabled. A session-only key may accompany an interactive operation; saved-key requests use an owner/purpose-validated credential ID. Monitoring never takes an arbitrary browser secret or key from a source URL. Public source URLs are validated server-side including safe redirects/DNS, not merely by Pydantic URL syntax.

String limits: recipient valid single address, subject 200 chars/no CRLF, email body/notes 10,000, question 2,000, per-answer 5,000 or field's lower limit, job excerpt 12,000. AI normalized token/output caps are in PROVIDERS. Source fetch has independent byte/page/time limits. Unknown source content isn't a successful no-jobs result.

## Extension messages

Envelope `{contract_version:1, request_id, operation, document_token?, payload}` with discriminated schemas. Validate sender extension/tab/frame/document using browser metadata, not page assertions. No externally_connectable/page postMessage command bridge/eval/remote adapter code.

| Operation | Authorized initiator | Meaning |
| --- | --- | --- |
| INSPECT_FORM / FORM_CHANGED | panel via worker / isolated script report | bounded selected-form metadata, invalidate affected bindings |
| ANALYZE_AND_AUTOFILL | trusted panel user action | context/profile/credential consent, prepare operation and write eligible values |
| APPLY_EDITED_VALUES | trusted panel user action | current exact edited revisions and field state |
| REPORT_FILL_RESULTS | isolated script | per-field verified result, no privileged commands |
| OBSERVE_SUBMISSION | isolated script → worker | bounded selected-session trusted user observation, idempotent metadata |
| FLUSH_TRACKING_OUTBOX | trusted worker | same ACTIVE account only; metadata replay, never fill/submit/generate |
| CONFIRM_SUBMITTED | trusted panel/dashboard user action | explicit date/source confirmation |

Scripts receive only target values, not keys/full profiles/private documents. Submission evidence is browser-reported observation, not independently verified delivery. Service restart clears write intent, retains only properly scoped session metadata/outbox. Poll AI/operations/run state or bounded dashboard polling; no websocket requirement in MVP. Badge refreshes on page load and at most every minute while visible.
