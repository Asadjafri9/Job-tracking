# DB-001 evidence

**Status:** DONE; implementation and independent review passed October 12, 2026.

**Implementation commit:** pending implementation commit.
**Independent review:** Codex, October 12, 2026. Passed fresh migration, idempotent rerun, nine PostgreSQL schema checks, Alembic metadata drift check, Ruff, mypy, and API suite. No acceptance gaps found within DB-001 scope.

**Scope:** SQLAlchemy 2 declarative v2 schema, PostgreSQL Alembic setup and initial revision, a loopback-only idempotent synthetic seed, and the V-DB script for DB-001. Runtime RLS/roles, application APIs, quota/idempotency protocols, concurrency handling, Azure, and production data are outside this task.

## Artifacts

- `apps/api/app/db/models.py`: 30 v2 tables covering identity/session metadata, profiles and immutable fact versions, private document metadata/extractions, encrypted provider credential metadata and ordered routes, AI attempts/operations, prepared application sessions, applications and event snapshots, monitored sources/runs/discovered jobs/notifications, durable jobs, idempotency, audit, and deletion journal. Provider routes reference both the owner's settings row and saved credential; fallback routes and background-enabled routes require separate shared consent revisions as well as per-credential purpose consent, consent revisions are positive when present, and revocation disables incompatible routes. Email evidence rejects both update and delete. Uses owner-scoped composite foreign keys where a child references an owner-bound parent; revisions/check constraints, partial/unique indexes, and explicit status constraints are represented in DDL.
- `apps/api/alembic/versions/0efe8de248fa_initial_v2_schema.py`: initial migration, generated from the model metadata and applied to a newly created empty local database.
- `apps/api/app/db/seed.py`: opt-in seed restricted to loopback URLs and `DB001_LOCAL_SEED=1`; inserts one fictional `.test` user, profile, preferred-role fact, and confirmed manual fact version with a confirmation timestamp. It does not include API keys or real personal data.
- `scripts/verify-database.sh`: refuses non-loopback database URLs, applies migrations, runs the opt-in seed, checks migration/model drift, and runs DB-001 PostgreSQL tests. Registered as `pnpm verify:database`.
- `apps/api/tests/test_db001_schema.py`: nine PostgreSQL-backed tests check migrated tables/head, owner-scoped FKs and named constraints/indexes, absence of plaintext provider-key columns, idempotent seed, cross-owner reference rejection, account-wide provider/route limits, separate positive fallback/background shared-consent gates and revocation, rejection of routes without settings, email live-document unlinking and immutable historical snapshots, JSON cardinality/serialized-byte bounds, confirmed-fact timestamps, scheduled-source consent, namespaced provider-native IDs, and update/delete-rejected idempotent email events.
