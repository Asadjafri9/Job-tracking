# M4 evidence — email applications

Scope implemented and verified on the loopback stack only. No Gmail OAuth,
no real email sending, no live provider call — sending is never part of
automated testing.

## MAIL-001 — draft API

- `apps/api/app/modules/emails.py`: `/email-drafts` CRUD under owner-scoped
  RLS. Recipient addresses are validated (simple address form, no CR/LF → no
  header injection), subject ≤200 chars, body ≤10,000 chars, employer/role
  cannot contain line breaks. A bounded non-canceled draft cap applies.
- Drafts snapshot confirmed EMAIL-permitted facts (`confirmed_facts_for_purpose`)
  plus selected READY style-document refs at create time; `generate` re-snapshots
  facts while preserving style entries.
- `POST /email-drafts/{id}/generate` runs the consent-gated `EMAIL` AI operation
  with `expected_revision` and a deterministic idempotency key; consent,
  provider-unavailable, quota, and UNKNOWN outcomes map to 403/503/429 and
  always preserve existing edits. Generated content is re-validated
  (subject cleaned/truncated to contract bounds, non-empty body required).
- `PATCH` requires `If-Match`; edits bump `revision` and return the draft to
  `READY_FOR_REVIEW`; `CANCELED`/`USER_CONFIRMED_SENT` are terminal.

## MAIL-002 — compose handoff

- `apps/web/src/ui/email.tsx`: fixed `https://mail.google.com/mail/` origin
  built only from the reviewed revision via `URLSearchParams`; no target URL
  ever comes from job/AI content. Links longer than 6,000 chars disable the
  Gmail button and explain the copy fallback — never silent truncation.
- Copy recipient/subject/message, a `mailto:` fallback, and explicit
  disclosure that opening Gmail moves the reviewed text into the
  browser/Gmail. No OAuth or connect prompt exists.
- `email.test.ts` verifies Unicode/newline/`&`/`+`/`#` round-trips and the
  fixed origin.

## MAIL-003 — honest send tracking

- `POST /compose-opened` records an idempotent `COMPOSE_OPENED` row in
  `email_draft_events` (client-supplied key; replay returns the same draft)
  and only flips state; tests assert no application exists afterward.
- `POST /confirm-sent` (sent date required) creates exactly one `EMAIL`
  `APPLIED` application per draft with an immutable snapshot (draft id,
  revision, recipient, subject, body, fact refs) and `USER_CONFIRMED_EMAIL`
  evidence linked through `email_draft_events`; same-revision or same-key
  repeats replay; sent drafts lock against edits.
- Selected style/attachment documents live in `email_draft_documents` with
  positional uniqueness and composite document+revision foreign keys.

## Codex review

`sol6.1` was attempted first and rejected by the account (HTTP 400); the
review ran on `gpt-6-luna` at high effort. It found one gap, fixed before
push: unsaved editor changes could be opened in Gmail or confirmed while the
tracked application snapshotted the older persisted revision — compose-open
and confirm-sent now persist pending edits first so the tracked revision
always matches what the user actually sends.

## Not verified here

Real Gmail compose behaviour (logged-out/multi-account states), live
provider generation quality, and real recipient delivery — by design,
sending live email is out of test scope.
