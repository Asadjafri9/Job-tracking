# M2 evidence — Onboarding and three-provider routing

Milestone: M2 (PROF-001, DOC-001, DOC-002, AI-001, AI-002, AI-003, DOC-003, AI-004)

Scope honestly recorded: all checks below were observed on the local loopback
stack (Docker PostgreSQL 17.6, Azurite emulator, fake OIDC, `LOCAL_TEST_KEK`
AES-GCM wrapper). **No live provider call, no real Key Vault operation, and no
real browser/extension session was performed.** Provider adapters are verified
only against stubbed `httpx.MockTransport` responses; model availability,
privacy-routing behavior, and structured-output support of real OpenRouter,
xAI, and Gemini endpoints remain unverified and gated on opted-in live
evaluation (V-L).

## Implemented surface

- **PROF-001** `app/modules/profile.py` + `apps/web/src/ui/profile.tsx`:
  `GET /profile` (ETag = profile revision), `PUT /profile/facts` (create with
  uniqueness on `fact_key`, 409 on duplicate), `POST /profile/facts/{id}`
  (immutable `ProfileFactVersion` per change, `If-Match`/`expected_revision`
  optimistic concurrency, 409 on stale revision), `DELETE` (soft-deactivate).
  Facts carry `value_type` (TEXT/NUMBER/DATE/BOOLEAN/LIST), `sensitivity`
  (NORMAL/SENSITIVE), `allowed_purposes` tags, `source_type`, and
  `confirmation_state`. Profile page lists editable facts with purpose badges.
- **DOC-001** `app/modules/documents.py` + `app/storage/blob.py` +
  `apps/web/src/ui/documents.tsx`: upload enforces ≤10 active documents,
  5 MiB/file (413), 50 MiB/account via `reserve_quota` (409), MIME +
  magic-signature validation for PDF/DOCX (422), SHA-256 hashing, immutable
  storage keys `user/doc/v{revision}/{sha16}`, private download through the
  runtime session only, soft delete that marks document-sourced fact versions
  `REVIEW_REQUIRED`, idempotency-key replay returning the original document,
  and a `document.parse` job enqueued in the same transaction as the READY
  state. Azurite backend plus an injectable `DocumentStorage` seam
  (`InMemoryDocumentStorage` in tests).
- **DOC-002** `app/worker/parsing.py` + `document.parse` handler in
  `app/worker/handlers.py`: extraction runs in a fresh subprocess
  (`python -m app.worker.parsing child`) with `RLIMIT_CPU` 15 s, a 256 MiB
  `RLIMIT_AS` bound on POSIX systems (macOS cannot lower address-space limits
  below the interpreter's mapped usage; the in-code caps bound allocation
  there), 64-fd limit, ≤50 pages, ≤100,000 extracted characters, DOCX ZIP
  expansion bounded at 25 MiB/1,000 entries with per-entry compressed-size
  checks. No macros, JavaScript, external fetches, or embedded-file rendering:
  only `pypdf`/`python-docx` text layers are read. Statuses: `OK`,
  `UNSUPPORTED` (unknown media, password-protected, scanned/no text layer),
  `FAILED` (malformed, oversized, timeout, process failure). Page/block
  anchors are stored per paragraph. The handler records `DocumentExtraction`
  with `parse_version` dedupe so a restarted worker does not double-store.
- **AI-001** `app/ai/contract.py`: `ContractModel` (extra=forbidden) input/
  output schemas for `EXTRACTION`, `JOB_MATCH`, `AUTOFILL`, `EMAIL`,
  `CLASSIFY`; `MODEL_CATALOG` restricting routing to evaluated models
  (`deepseek/deepseek-v4-flash`, `grok-4.7`, `gemini-3.8-flash`); output-token
  ceilings (4,000 autofill / 1,500 email / 2,000 extraction/classification /
  job context); `output_schema_for` JSON-Schema export for provider-side
  structured output; `validate_input`/`validate_output` authoritative
  validation; ≤12,000-token input estimate gate.
- **AI-002** `app/ai/providers.py`: `ProviderAdapter` protocol with
  `OpenRouterAdapter`, `XaiAdapter`, `GeminiAdapter` over pinned base URLs,
  httpx timeouts, no tools, no browsing. OpenRouter requests set
  `provider.data_collection="deny"` and `provider.sort` privacy routing hints.
  Every response is normalized to `AttemptOutcome` kinds `SUCCESS`,
  `EXHAUSTED`, `RATE_LIMITED`, `UNAVAILABLE`, `INVALID_KEY`, `BAD_INPUT`,
  `REFUSAL`, `UNKNOWN` with provider/model/usage metadata; success content is
  validated against the operation schema before being accepted.
- **AI-003** `app/ai/router.py`: consented dispatch with the PROVIDERS.md
  outcome state machine — `EXHAUSTED`/`UNAVAILABLE` try the next eligible
  route (fallback consent required for multi-route), definitive 429 gets one
  bounded short retry inside the 60 s deadline, `INVALID_KEY` marks the
  credential `NEEDS_ATTENTION` and falls through only with consent,
  `BAD_INPUT`/`REFUSAL` stop immediately without charging other providers,
  `UNKNOWN` records the state with no automatic retry or fallback. Daily
  ceilings enforced before dispatch: 50 interactive ops, 5 classification
  ops, 150 attempts, one active interactive op per account. Stable idempotency
  key + input HMAC replays return the recorded result without redispatch.
  Key unwrap happens only inside the owner-scoped transaction for the single
  outbound call; no plaintext enters operations, attempts, prompts, or logs.
- **DOC-003** `document.extract_candidates` durable job +
  `app/modules/extractions.py` + review UI on the documents page: after a
  `PARSED` extraction the parse handler enqueues a separate extraction job in
  the same transaction, which builds bounded anchored sections and dispatches
  `EXTRACTION` through `run_operation` with `BACKGROUND` purpose and a
  deterministic `uuid5` idempotency key (restart-safe, no redispatch).
  Missing background/provider consent leaves the candidate list empty and the
  extraction in `REVIEW_REQUIRED` — manual entry stays available. Provider
  failures set `review_state=FAILED` with a content-free routing code; a
  deleted or replaced source skips dispatch entirely.
  `GET /documents/{id}/extractions` returns the stored extraction with
  anchored `source_anchors` and per-candidate state;
  `POST /extractions/{id}/candidates/{index}/decision` with `CONFIRM`/`REJECT`.
  Confirm creates/updates the `ProfileFact` and writes a `DOCUMENT`-sourced
  `ProfileFactVersion` carrying `document_id`, `document_revision`,
  `page_number`, and the source anchor — nothing auto-confirms; decisions are
  one-shot (409 on re-decision); deleting a source marks its confirmed
  versions `REVIEW_REQUIRED`.
- **AI-004** `apps/api/tests/corpus/*.json` + `tests/test_ai_corpus.py`: nine
  recorded cases across all five operation kinds — each validates the input
  schema, accepts a well-formed output, and rejects schema-violating or
  source-reference-violating outputs (absent `section_id`, unknown
  `field_id`, unprovided `used_fact_keys`/`option_ids`, absent `native_id`,
  over-bound lengths). No prompt/model evidence is claimed because no live
  provider run occurred.
- **Migration `3b8e1f0a2c45`**: extends `ai_operation_kind` with `EXTRACTION`
  and `CLASSIFY` and `document_type` with `SUPPORTING_DOCUMENT`, including
  the matching VARCHAR length adjustments; verified via `alembic check`.

## Known boundaries (not claimed)

- Live provider behavior is stub-verified only; real endpoint evaluation is
  gated on opted-in keys (V-L). Model catalog changes must surface as
  configuration issues, not silent upgrades — there is no live check yet.
- The 256 MiB memory bound is enforced by `RLIMIT_AS` on Linux/POSIX; on
  macOS the kernel rejects limits below the interpreter's mapped address
  space, so the bound is enforced there by the in-code caps (25 MiB ZIP,
  100k chars, 50 pages) and CI on Linux.
- The extraction job requires `BACKGROUND` consent — an account with only
  interactive consent gets the parse/anchors but no AI candidates until it
  consents (per PROVIDERS.md; the consent toggle lives on the providers
  page). There is no manual "re-run extraction" endpoint yet; replacing the
  document is the regeneration path.
- Extraction quality against real resumes is unproven; the corpus is an
  offline contract check, not a model evaluation.
