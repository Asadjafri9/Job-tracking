# M3 evidence — autofill, tracking and dashboard

Scope implemented and verified on the loopback stack only (Docker PostgreSQL,
fake OIDC, no Azure, no live hiring sites, no provider calls).

## APP-001 — sessions and URL identity

- `apps/api/app/modules/applications.py`: `/application-sessions` CRUD with
  canonical HTTPS URL normalization (`utm_*`/`fbclid`/`gclid`/`ref` tracking
  params stripped, fragment dropped, host lower-cased), open-session bound,
  `ANALYZING`/`READY_TO_REVIEW`/`ABANDONED`/`SUBMISSION_ATTEMPTED` states, and
  `If-Match`/expected-revision checks. Selected fact and document versions are
  validated and snapshotted at create time (409 on stale/missing/unconfirmed).
- `tests/test_applications_api.py` (12 tests, PostgreSQL-backed):
  canonicalization, HTTPS enforcement, fact-revision conflicts, session
  ownership under RLS.

## APP-002 / TRACK-003 — evidence, history, snapshots

- `POST /submission-events` is idempotent on `event_idempotency_key`
  (`replayed: true`), rejects observations outside a bounded ±window, and
  requires a valid `gesture_ref_hash`. `SUBMIT_CLICK`/`UNKNOWN` creates exactly
  one `WEB_FORM` application per session at `SUBMISSION_ATTEMPTED` — a click is
  never Applied. `VALIDATION_BLOCKED`/`SITE_SIGNAL` attach without advancing
  status.
- `application_status_events` are append-only; `Application.context_snapshot`
  and `document_metadata_snapshot` are immutable copies of the session state.
- `POST /application-sessions/{id}/applied-answers` records what was actually
  filled under `expected_context_revision` binding; snapshot code prefers
  applied entries (user edits win) and falls back to drafts, preserving
  `used_fact_keys`/provider/model provenance in `application_answers`.
- `POST /applications/{id}/confirm` requires an explicit `applied_date`;
  `APPLIED` without a date is rejected at both create and confirm paths.

## APP-003 — dashboard and UI

- `GET /dashboard` returns `prepared_sessions` and `applications_by_status`
  counts separately plus bounded `upcoming_follow_ups` (7 days) and recent
  status events.
- `apps/web/src/ui/applications.tsx`: stat cards, status/search filters,
  manual tracking form, history + confirm-applied flows using `If-Match`
  revisions, accessible loading/error/empty states, responsive table/toolbar.

## TRACK-001/002 — passive observation and outbox

- `apps/extension/src/worker.js`: trusted submit-intent/validation/native
  observations map to `SUBMIT_CLICK`/`VALIDATION_BLOCKED`/`SITE_SIGNAL`
  evidence with a hashed gesture reference and deterministic idempotency key,
  and only inside a prepared session bound to the current tab+document
  handles.
- `apps/extension/src/outbox.js`: 32-entry, 4 KB, 24 h metadata-only queue
  persisted in `chrome.storage.local`, keyed to the hashed extension token;
  dedupes on the server idempotency key, retries only transient failures
  (8 attempts), drops 4xx/expired/foreign entries, flushes on
  enqueue/sign-in/service-worker restart, and purges on sign-out.
- `test/extension.test.mjs`: 22 tests including sanitize allowlist, bounded
  capacity, account-bound flush, TTL expiry, and terminal-failure drop.

## EXT-004/005/006 — session wiring (in progress for live gates)

- `panel-prepare-tracking` creates a session with the page URL + captured job
  excerpt; `panel-draft-answers` sends bounded ordinary questions (≤10, option
  labels, sensitive types excluded at extraction) with
  `expected_profile_revision`; `panel-apply-reviewed-values` reports per-field
  outcomes under `expected_context_revision`. Drafted `option_ids` resolve
  only to verified option values; sensitive/attestation fields remain manual;
  nothing is ever submitted.

## Codex review

`sol6.1` was attempted first and rejected by the ChatGPT account (HTTP 400,
"not supported when using Codex with a ChatGPT account"); the review ran on
`gpt-6-luna` at high effort, matching the M1/M2 fallback. It found three
gaps, all fixed and covered by tests:

- **CSRF header dropped on status mutations** (web `api()` spread order) —
  options headers now merge instead of replacing.
- **Sessions created without confirmed facts** — `panel-prepare-tracking`
  now snapshots every CONFIRMED AUTOFILL-permitted fact at its revision.
- **Sessions never expired** — sessions now carry a 24 h `expires_at`;
  expired sessions are excluded from the open-session limit and dashboard
  count, and reject drafts/applied-answers/submission events with 409.
