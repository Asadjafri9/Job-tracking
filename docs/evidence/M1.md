## Implemented and verified in this checkout

- `DB-001`: v2 entities, constraints, and fresh migrations; completed earlier with independent review.
- `DB-002`: runtime tenant RLS, transaction-scoped owner context, hash-scoped authentication lookups, and jobs-only worker role. See [DB-002 evidence](DB-002.md).
- `DB-003`: optimistic revisions, HMAC idempotency, and expiring per-owner quota reservations. Added concurrent PostgreSQL checks. See [DB-003 evidence](DB-003.md).
- `AUTH-001`–`AUTH-004`: Authlib constructs the authorization-code/PKCE request and exchanges the code; its token session disables redirects to prevent forwarding the code or client secret. Joserfc verifies RS256/JWKS and local-only HS256 test tokens; strict issuer, audience, authorized-party, nonce, and time checks remain application-enforced. Local web session/CSRF/logout, extension grant exchange, and fake identity lifecycle pass. The local flow uncovered and fixed `FOR UPDATE` calls that exceeded the auth role's table grants; enrollment uses conflict-safe inserts without broader user-table permissions.
- `KEY-001`–`KEY-002`: encrypted saved-key and provider consent APIs; end-to-end local tests cover masking, consent revision checks, revocation, and consent reset.
- `JOB-001`: durable enqueue/claim/heartbeat/retry/cancel code; PostgreSQL checks cover concurrent claims, retry exhaustion, worker data isolation, and reclaim after a simulated process restart; worker-loop unit checks cover idle and graceful shutdown.
- `JOB-001` scheduler: `app/worker/scheduler.py` ticks every minute through a dedicated `copilot_scheduler` role. Each tick locks due ACTIVE daily sources (`FOR UPDATE`, `SKIP LOCKED` candidate scan plus a per-source locked re-check), inserts the unique `(source_id, scheduled_local_date)` `DAILY` run, enqueues one `monitoring.daily_scan` job per run via the `uq_jobs_active_reference` partial index, and advances `next_run_at` to the next 09:00 in the source's IANA timezone. Restart catch-up replays at most one missed slot inside a six-hour window and records older missed slots as `SKIPPED` runs (`missed_dispatch_window`). Missed-slot iteration is bounded at 32 slots per tick per source and the candidate scan at 200 sources.
- `JOB-001` handlers: `app/worker/handlers.py` registers `monitoring.daily_scan` and `maintenance.owner_cleanup` through the shared `app/worker/registry.py` registry, which `runner.py` re-exports so `python -m app.worker.runner` cannot split handler registration across a `__main__` module copy. Handlers claim under `copilot_worker` and perform owner work in a transaction-scoped `tenant_session` runtime transaction using the job row's `user_id`, never job-body input. The daily scan handler revalidates run state, source schedule, and consent/schedule revision before any fetch work and records an honest terminal outcome (`CANCELED` when stale, `FAILED`/`daily_scan_pipeline_pending_m5` until the M5 fetch/match pipeline exists). The cleanup handler deletes only expired/consumed sessions, extension grants, idempotency records, and quota reservations for the job's verified owner.
- `KEY-002` production UI: `apps/web/src/ui/providers.tsx` implements the AI-providers settings screen (nav: "AI providers") over the generated OpenAPI contract — saved-key cards with masked `last4`, purpose consent checkboxes on save, delete with fresh-auth messaging, and a routing/consent section that sends `expected_revision` plus an `If-Match` header, reloads on 409, and explains consent purposes per the DGN-005 prototype copy. Pure helpers live in `provider-utils.ts` with unit tests.
- OIDC hardening: discovery endpoints must be HTTPS or true loopback HTTP hosts; RS256/JWKS validation, nonce/audience/authorized-party checks, and rejection of malformed or insecure endpoint cases have tests.
- Updated generated OpenAPI and TypeScript client artifacts.
