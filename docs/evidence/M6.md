# M6 evidence — privacy, reliability and quality

Scope verified locally on the loopback stack (Docker PostgreSQL with the real
least-privilege roles, Azurite, fake OIDC). No Azure, provider, Gmail or
Chrome contact. Commit: this milestone's merge commit on `work`.

## DATA-001 — lifecycle/cleanup/cancel stages

- `maintenance.owner_cleanup` now also abandons expired application
  sessions (`PREPARED`/`ANALYZING`/`READY_TO_REVIEW` past `expires_at` →
  `ABANDONED`), cancels stale email drafts (`DRAFT`/`READY_FOR_REVIEW`/
  `COMPOSE_OPENED` older than 30 days → `CANCELED`), cancels expired
  `QUEUED` jobs, expires `BUILDING` export artifacts older than one hour
  (`build_timeout`), and expires `READY` artifacts past `expires_at`,
  deleting their private blobs after commit. Bounded to the job owner's
  rows inside one transaction; restart-safe because unprocessed rows
  simply remain for the next tick.
- Source deletion continues to block dispatch (`_claim_scan`), and the
  publish path now also re-checks owner `ACTIVE` state before applying a
  fetched scan outcome — a scan that finishes after deletion records
  `CANCELED/account_not_active` and writes nothing.
- Key/document/source removal paths already stop future work
  (`original_state=DELETED` guards, `status=REVOKED` consent checks);
  blob removal uses the durable `document.blob_cleanup` job (M2 fix).

## DATA-002 — export v2/snapshot/ZIP/privacy UI

- `export_artifacts` table (migration `c6f2a9d84b17`): owner-scoped RLS
  policy for `copilot_runtime`, `BUILDING/READY/EXPIRED/DELETED` states,
  bounded storage key/SHA-256/size, `expires_at`.
- `POST /api/v1/export-requests` is idempotent while an artifact is
  `BUILDING`; `GET /export-requests` lists the latest 20;
  `GET /export-requests/{id}/download` streams the private blob only when
  `READY` and unexpired (410 otherwise, 404 for other owners).
- `privacy.export` durable job builds the ZIP inside one owner
  transaction (consistent snapshot), writes the blob to the private
  container under `exports/{owner}/{artifact}.zip`, re-checks owner
  `ACTIVE` before publishing, then marks `READY` with a fresh 24-hour
  `expires_at`.
- ZIP contents: `manifest.json` (schema_version 2, generated_at,
  timezone, per-member SHA-256), `data/*.json` + `data/*.csv` for
  profile/facts/versions, documents/extractions, provider
  settings/routes, application sessions/applications/submission
  events/status events/answers, email drafts, monitored
  sources/runs/discovered jobs/notifications and audit events, plus
  `originals/` document blobs (bounded at 50 MiB, sanitized member
  names).
- Secret exclusion is enforced twice: `_rows` drops the deny-list
  columns (ciphertext, nonce, wrapped_dek, kek_version, key_last4,
  token/session/verifier hashes, integrity_hmac, storage keys, lease
  fields, encrypted cleanup payloads) and `_assemble_zip` strips them
  again defensively.
- CSV cells are formula-escaped (`=`, `+`, `-`, `@`, tab, CR prefixes
  get a leading `'`); member names are fixed safe ASCII paths.
- Privacy page (`#privacy`, shield nav icon): request/list/download
  exports with state badges and expiry, plus the typed-consent deletion
  flow. Responsive/accessible conventions match the rest of the shell
  (labels, `aria-live`, `role=alert`).

## DATA-003 — account delete/journal/receipt

- `POST /api/v1/account/deletion` requires authentication within the
  last 10 minutes plus the typed body `{"confirmation": "DELETE"}`.
- Stage 1 (single transaction, before acknowledgement): journal
  existence/idempotency check, `copilot_begin_deletion()` marks the user
  `DELETING` (row-locking UPDATE inside a SECURITY DEFINER function),
  all live sessions revoked, every provider credential `REVOKED` with
  key material zeroed, monitored sources `DELETED` with schedules
  cleared, queued monitoring runs and queued jobs `CANCELED`, then the
  independent `deletion_journal` row is written — `user_id_hash`,
  revoked credential versions, revoked-session digest, integrity HMAC —
  before the receipt (`operation_id`, `DELETING`, `journal_hmac`,
  30-day receipt expiry) is returned.
- `users` is deliberately outside tenant RLS (auth bootstrap does
  subject lookups before `user_id` is known). Runtime self-access is
  mediated by the `copilot_current_user` view (row filtered by
  `app.user_id` GUC) plus `copilot_begin_deletion()` and
  `copilot_tombstone_user()` SECURITY DEFINER functions — no direct
  UPDATE/DELETE grant on `users`.
- `privacy.account_delete` durable job (stage 2): refuses to run without
  a journal row, collects document/export blob keys inside the owner
  transaction, deletes blobs outside it (logged best-effort), then in a
  second transaction re-checks `DELETING`, deletes every tenant table in
  FK-safe order (including the job row itself — `finish_job` no-ops on
  the missing row), and tombstones the identity row
  (`state=DELETED`, `login_email` → `deleted-<uuid>@tombstone.invalid`).
- Late-result guards: scan publish and export publish both re-check
  owner state; `POST /export-requests` returns 409 for non-`ACTIVE`
  accounts; parse/extract jobs early-return on deleted documents;
  `copilot_begin_deletion` only transitions `ACTIVE` → `DELETING`, so a
  second request hits the journal's 409 instead.
